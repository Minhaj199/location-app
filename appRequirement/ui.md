Redesign the UI of my location-based alarm Android app using a distinctive, human-designed visual identity.

### Design direction

The app is a **location-based alarm app**. The visual language should communicate:

* Location/navigation → trustworthy, calm, stable
* Alarm/alerts → noticeable but not aggressive
* Overall feeling → minimal, practical, premium, slightly distinctive

**Avoid the generic AI/SaaS aesthetic.**

Do NOT use:

* Purple + blue gradients
* Cyan/purple combinations
* Neon colors
* Excessive gradients
* Glassmorphism
* Excessive rounded cards
* Floating blobs or decorative abstract shapes
* Excessive shadows
* Generic dashboard styling
* Excessive use of icons
* Huge typography for decoration

### Color palette

Use this palette consistently:

* Primary / Deep Navy: `#172033`
* Primary Light / Slate Blue: `#34415A`
* Background / Warm Off-White: `#F7F5F0`
* Surface / White: `#FFFFFF`
* Accent / Warm Amber: `#E6A23C`
* Main Text: `#171A21`
* Secondary Text: `#697386`
* Success / Forest Green: `#3F7652`
* Error / Muted Red: `#B94A48`
* Border: `#DCDDD8`

Do not introduce additional prominent colors unless absolutely necessary.

### Color usage

Follow approximately this visual balance:

* 70% neutral/background colors
* 20% primary dark colors
* 8% secondary/muted colors
* 2% accent colors

Use **Warm Amber only for meaningful alarm-related actions or states**, not as a general decorative color.

Use Deep Navy for:

* Primary buttons
* Navigation
* Important controls
* Selected states

Use Warm Off-White for the main background.

Use White for cards and elevated surfaces.

Use Forest Green for enabled/active/success states.

Use Muted Red only for destructive/error states.

### UI style

Use:

* Clean typography
* Strong visual hierarchy
* Moderate corner radius
* Thin, subtle borders
* Very restrained shadows
* Generous but practical spacing
* Clear touch targets
* Consistent iconography
* Strong alignment and grid discipline

The UI should feel like a **real product designed by a thoughtful product designer**, not an AI-generated concept.

### Location alarm screen

The main screen should make the user's alarms immediately understandable.

Each alarm should clearly communicate:

* Place name
* Location/radius
* Active/inactive state
* Alarm status
* Relevant action

Example structure:

Home
500 m
Active

Railway Station
800 m
Inactive

Do not overcrowd the cards.

### Map/location experience

The location-selection experience should prioritize the map and location information.

Use the color palette subtly. Do not recolor the entire map or add unnecessary decorative elements.

The selected location and radius should be visually obvious.

### Alarm creation

The alarm creation flow should be simple:

1. Select location
2. Set radius
3. Configure alarm/message
4. Review
5. Activate

Make the primary action visually clear using Deep Navy.

Use Amber sparingly to indicate that an alarm is active or about to trigger.

### Important

Do not redesign the app into a generic finance/dashboard/SaaS interface.

Do not invent unnecessary features.

Preserve the existing functionality and architecture.

Focus on:
**clarity → hierarchy → usability → distinctive visual identity.**

Before implementing, inspect the existing screens/components and reuse existing functionality where possible. Refactor only where necessary to achieve the new design.

The final result should look cohesive across:

* Home
* Alarm creation
* Location selection
* Alarm details
* Settings
* Empty states
* Active/inactive states
* Error states

Use the same spacing, typography, component shapes, borders, and color rules throughout the application.
